# Полная инструкция выполнения практической работы

## 1. Развёртывание реальной лабораторной WordPress-среды
Требуется Docker Desktop/Engine с Docker Compose v2. Команды выполнять из корня репозитория.

1. Создайте локальный файл окружения (он исключён из Git):
   ```bash
   cp lab/.env.example lab/.env
   ```
2. Обязательно замените оба пароля в `.env` на длинные уникальные значения.
3. Запустите стенд:
   ```bash
   docker compose -f lab/docker-compose.yml up -d
   docker compose -f lab/docker-compose.yml ps
   ```
4. Откройте http://localhost:8080 и завершите установку WordPress. При установке используйте отдельную лабораторную учётную запись администратора.
5. Проверьте, что сайт и /wp-login.php открываются.

Стенд использует MariaDB и официальный образ WordPress Apache/PHP. Данные сохраняются в именованных Docker volumes. Не используйте пароли из примера на публичном сервере.

## 2. Применение базового и среднего уровней
После установки выполните:
```bash
bash scripts/harden-and-audit.sh
bash scripts/http-security-test.sh
```
Скрипт hardening удаляет стандартные readme.html/license.txt и резервные файлы только в корне лабораторного WordPress, назначает каталоги 755, файлы 644 и wp-config.php 440, устанавливает uploads/.htaccess и проверяет ключевые директивы. HTTP-тест создаёт временный PHP-файл в uploads, проверяет запрет доступа к wp-config.php и тестовому PHP, а затем гарантированно удаляет тестовый файл.

Ожидаемые коды до переноса конфигурации: `/wp-config.php` — 403; `/wp-content/uploads/security-test.php` — 403. Если Apache не разрешает .htaccess или правила не применяются, сначала проверьте конфигурацию виртуального хоста и AllowOverride.

## 3. Продвинутый уровень: перенос wp-config.php
Сделайте резервную копию перед переносом. В лабораторном Docker-стенде выполните:
```bash
bash scripts/move-config-outside-webroot.sh
```
Скрипт временно убирает копию конфигурации из DocumentRoot, проверяет главную страницу и wp-login.php, затем удаляет rollback-копию при успехе. При ошибке автоматически возвращает конфигурацию в web-root. После успешного переноса файл находится в `/var/www/wp-config.php`, выше `/var/www/html`.

После переноса запрос `/wp-config.php` обычно возвращает 404, поскольку файла больше нет в DocumentRoot. До переноса .htaccess должен возвращать 403. Для методички зафиксируйте оба этапа отдельно, а для отчёта по переносу приложите дерево каталогов и работающую главную страницу.

## 4. Аудит префикса таблиц
В свежей лабораторной установке Compose передаёт префикс `sec_lab_`. Проверьте фактическую строку в конфигурации. Стандартный `wp_` известен и делает типовые имена таблиц предсказуемыми при разведке схемы. Уникальный префикс затрудняет угадывание, но не устраняет SQL-инъекции и не заменяет параметризованные запросы и минимальные права БД.

## 5. Что проверить в административной панели
Войдите в `/wp-admin`. При `DISALLOW_FILE_EDIT=true` встроенные редакторы кода тем и плагинов должны быть отключены. Сделайте скриншот меню без секретов.

## 6. Сбор доказательств
Сохраните фактические скриншоты:
1. Корень сайта после удаления информационных и резервных файлов.
2. Права wp-config.php (400/440), каталоги 755 и файлы 644.
3. Ответ 403 на /wp-config.php до переноса.
4. Ответ 403 на временный PHP в uploads и содержимое локального .htaccess.
5. Меню wp-admin без редакторов.
6. Фрагмент debug-констант без паролей/солевых ключей.
7. Дерево каталогов после переноса и открытая главная страница.
8. Строка фактического $table_prefix без иных секретов.

Вставьте изображения в `docs/ОТЧЕТ.md` или DOCX. Не подменяйте их макетами или текстовыми заглушками. Не публикуйте настоящий wp-config.php, пароли, salts, дампы БД и debug.log.

## 7. Завершение лаборатории
Для остановки:
```bash
docker compose -f lab/docker-compose.yml down
```
Для удаления контейнеров вместе с данными лабораторной БД (необратимо):
```bash
docker compose -f lab/docker-compose.yml down -v
```
На публичном production-сайте после лабораторной диагностики выключите WP_DEBUG и храните логи вне публичного доступа. На Nginx .htaccess не работает — эквивалентные правила нужно задавать в конфигурации Nginx.
