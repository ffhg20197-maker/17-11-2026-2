## 2. Лабораторная среда

Для воспроизводимого тестирования создана изолированная среда Docker Compose: WordPress + MariaDB. Скрипты автоматизации находятся в `scripts/`, конфигурационные шаблоны — в `lab/`, проверки GitHub Actions — в `.github/workflows/wordpress-security-lab.yml`. Секреты production-сайта не используются; файл `lab/.env` локальный и не должен публиковаться.

## 3. Описание выполненных мер

### 3.1. Очистка корня

Удаляются/проверяются `readme.html`, `license.txt`, а также резервные копии и дампы `.sql`, `.zip`, `.bak`. Публикация таких файлов опасна, поскольку они могут раскрывать исходный код, содержимое БД и персональные данные.

### 3.2. Права доступа

- Каталоги: `755`.
- Обычные файлы: `644`.
- `wp-config.php`: `440`.

Права 440 ограничивают запись и чтение посторонними пользователями. Владелец и группа должны соответствовать реальному пользователю веб-процесса, иначе PHP не сможет прочитать конфигурацию.

### 3.3. Защита конфигурации

Для Apache/LiteSpeed используется правило:

```apache
<FilesMatch "^(wp-config\\.php|\\.htaccess|\\.htpasswd|readme\\.html|license\\.txt)$">
    Require all denied
</FilesMatch>
Options -Indexes
```

В CI запрос `/wp-config.php` до переноса получил HTTP 403. Для Nginx необходимо отдельное правило в конфигурации виртуального хоста, поскольку Nginx не обрабатывает .htaccess.

### 3.4. Запрет PHP в uploads

Файл `wp-content/uploads/.htaccess` запрещает выполнение PHP-подобных расширений:

```apache
<FilesMatch "(?i)\\.(php[0-9]?|phtml|phar|phps)$">
    Require all denied
</FilesMatch>
Options -ExecCGI
```

CI создаёт временный `security-test.php`, проверяет HTTP-ответ и удаляет тестовый файл. Результат — HTTP 403.

### 3.5. Константы WordPress

```php
define('DISALLOW_FILE_EDIT', true);
define('WP_DEBUG', true);
define('WP_DEBUG_DISPLAY', false);
define('WP_DEBUG_LOG', true);
@ini_set('display_errors', '0');
```

`DISALLOW_FILE_EDIT` отключает встроенный редактор тем и плагинов. Ошибки записываются в журнал, но не выводятся посетителям. Важно: `WP_DEBUG=true` используется в лабораторной диагностике; после проверки на production его следует отключить или перенаправить журнал в защищённое хранилище. `debug.log` не должен быть публично доступен.

### 3.6. Перенос wp-config.php

Конфигурация переносится из `/var/www/html/wp-config.php` в `/var/www/wp-config.php`, то есть выше DocumentRoot. После переноса проверяются главная страница и `/wp-login.php`. Оба URL должны вернуть HTTP 2xx. Прямой доступ к `/wp-config.php` после переноса должен оставаться закрытым (HTTP 403 или 404).

### 3.7. Префикс таблиц

В тестовой среде подтверждён префикс `sec_lab_`. Стандартный `wp_` предсказуем и упрощает угадывание типовых имён таблиц. Нестандартный префикс снижает предсказуемость, но не устраняет SQL-инъекции и не заменяет подготовленные запросы, обновления и минимальные права пользователя БД. Для существующей базы смена префикса требует миграции таблиц и связанных значений.
