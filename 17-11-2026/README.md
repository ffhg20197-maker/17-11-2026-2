# WordPress Security Hardening — Тема 3.2.49

Практический комплект по защите файловой структуры WordPress (17.11.2026).

## Состав
- `.htaccess` — защита корня сайта (Apache 2.4).
- `uploads/.htaccess` — запрет исполнения PHP в загрузках.
- `wp-config.sample.php` — безопасный фрагмент конфигурации без секретов.
- `tools/audit.php` — read-only аудит файлов и прав.
- `docs/ПОРЯДОК_ВЫПОЛНЕНИЯ.md` — пошаговое руководство и проверки.
- `docs/ОТЧЕТ.md` — отчёт по критериям и места для фактических доказательств.
- `site-preview/index.html` — статическая демонстрационная страница проекта (не реальная админка WordPress).

## Важно
Репозиторий содержит подготовленные конфигурации и проверочный инструментарий. Он не подключён к вашей установке WordPress или хостингу. Поэтому реальные CHMOD, HTTP 403, перенос `wp-config.php` и скрытие редактора в админке должны быть выполнены и проверены на вашем тестовом сервере. Не считайте их подтверждёнными только по наличию файлов.

## Быстрый старт
1. Сделайте резервную копию файлов и БД.
2. Сверьте конфигурацию с версией Apache и текущими правилами сайта.
3. Скопируйте корневой `.htaccess` в web-root, а `uploads/.htaccess` — в `wp-content/uploads/`.
4. Перенесите настройки из `wp-config.sample.php` в существующий `wp-config.php`, не заменяя секреты и параметры БД.
5. Запустите аудит: `php tools/audit.php /path/to/wordpress`.
6. Пройдите чек-лист из `docs/ПОРЯДОК_ВЫПОЛНЕНИЯ.md`.

## Совместимость
Правила `Require all denied` рассчитаны на Apache 2.4+. Для Nginx правила из .htaccess не действуют — используйте отдельные location-блоки из руководства. На LiteSpeed совместимость обычно сохраняется, но проверьте конфигурацию хостинга.

## Безопасность
Не коммитьте настоящий `wp-config.php`, дампы БД, пароли, API-токены или production-журналы. Уникальный `$table_prefix` лучше задавать при новой установке. Смена префикса существующего сайта требует отдельной миграции БД и проверки сериализованных данных.
